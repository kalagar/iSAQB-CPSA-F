Learning objectives

By the end of this lesson, you should be able to explain and apply the core ideas behind Stakeholders, views, rationale in both exam questions and real architecture discussions.

Official alignmentLG 01-06 and LG 02-01 — Stakeholders and Concerns.

Stakeholders and concerns

A stakeholder is anyone with an interest in the system. A concern is something they care about.

Stakeholder

Developer, Product Owner, SRE, Security Officer, CFO, customer, regulator.

Concern

Maintainability, delivery speed, uptime, security, cost, compliance, usability.

One stakeholder can have many concerns, and one concern can affect many stakeholders.

Different stakeholders need different views

The same architecture should be communicated differently depending on the audience.

  • Developers need component responsibilities and interfaces.
  • SREs need runtime and deployment behavior.
  • Management needs risks, costs, and strategic consequences.
  • Security needs trust boundaries, identities, and data flows.

Communicate rationale, not just decisions

Context → Options → Decision → Rationale → Consequences

A decision without rationale is difficult to evaluate later. Good architecture documentation preserves why a choice was made.

Staff Engineer lens

Communication skillStaff Engineers frequently explain the same architecture at multiple abstraction levels—from code-level details to business impact.

Common CPSA-F exam traps

  1. Every stakeholder needs the same view. — Treat this as suspicious or false unless the context explicitly supports it.
  2. Concerns map one-to-one to stakeholders. — Treat this as suspicious or false unless the context explicitly supports it.
  3. Technical correctness alone guarantees successful architecture communication. — Treat this as suspicious or false unless the context explicitly supports it.

Key terms to remember

StakeholderA person or group with an interest in the system.
ConcernSomething a stakeholder cares about.
Architectural viewA representation tailored to a set of concerns.
RationaleThe reason why a decision was made.

Practical exercise

A healthcare platform plans to move from a monolith to microservices on Kubernetes. Stakeholders: Product Owner, Backend Developer, Security Officer, SRE, CFO.

For each stakeholder, identify two likely concerns and the architectural view you would show them first.

Review questions

What is a stakeholder?

A person or group with an interest in the system.

What is a concern?

A topic or quality a stakeholder cares about.

Should every stakeholder receive the same architecture documentation?

No. Different concerns require different views and levels of detail.

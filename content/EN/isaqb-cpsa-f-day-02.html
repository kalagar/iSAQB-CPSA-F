Learning objectives

By the end of this lesson, you should be able to explain and apply the core ideas behind Architect role, responsibilities, collaboration in both exam questions and real architecture discussions.

Official alignmentLG 01-04 — Tasks and Responsibilities of Software Architects.

What architects are responsible for

Software architects do more than create diagrams. They clarify requirements and constraints, shape the system structure, define interfaces and dependencies, choose cross-cutting concepts, communicate decisions, and support implementation over time.

Clarify → Design → Communicate → Validate → Evolve
Exam focusRemember the architect's role as a continuous responsibility across design, implementation, and evolution—not a one-time upfront activity.

Seven responsibilities to remember

  1. Clarify functional requirements, quality requirements, and constraints.
  2. Decompose the system into meaningful building blocks.
  3. Define responsibilities, interfaces, and dependencies.
  4. Make decisions about cross-cutting concerns such as security, logging, persistence, caching, and monitoring.
  5. Document and communicate architecture to different stakeholders.
  6. Support implementation and incorporate feedback.
  7. Evaluate architecture, risks, trade-offs, and consequences.

Architect vs. Project Manager

Architect

Owns technical structure, quality trade-offs, architectural risks, and major technical decisions.

Project Manager

Owns planning, schedule, budget, coordination, delivery tracking, and project organization.

There can be overlap in collaboration, but the responsibilities are not interchangeable.

Staff Engineer lens

Practical Staff behaviorA Staff Engineer often performs architectural responsibilities without necessarily having “Architect” in the job title: aligning teams, clarifying quality goals, identifying risks, and explaining decision consequences.

Common CPSA-F exam traps

  1. Architects are only responsible for diagrams. — Treat this as suspicious or false unless the context explicitly supports it.
  2. Architecture is completed before implementation starts. — Treat this as suspicious or false unless the context explicitly supports it.
  3. Project management and architecture responsibilities are identical. — Treat this as suspicious or false unless the context explicitly supports it.

Key terms to remember

Architectural responsibilityA duty related to shaping, communicating, validating, and evolving the system architecture.
Cross-cutting concernA concern such as security, logging, monitoring, or persistence that affects many parts of the system.
Architecture riskA technical uncertainty or weakness that may threaten important goals.

Practical exercise

You are designing a banking app with these statements:

  • Users can transfer money.
  • Transfers must never be lost.
  • 99.99% availability.
  • Every transaction is auditable.
  • Java and PostgreSQL are mandatory.
  • 8 developers.
  • 6-month deadline.

Classify each item as functional requirement, quality requirement, or constraint. Then identify three architecture risks the architect should investigate early.

Review questions

What are the architect's core responsibilities?

Clarifying requirements, designing structure, defining interfaces and cross-cutting concepts, communicating architecture, supporting implementation, and evaluating risks and trade-offs.

Does an architect stop working after the initial design?

No. Architecture is iterative and architects support implementation and evolution.

Is a project manager responsible for architecture decisions?

Not primarily. The project manager owns delivery coordination; the architect owns major technical structure and decisions.

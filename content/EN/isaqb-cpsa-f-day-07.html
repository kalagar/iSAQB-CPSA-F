Learning objectives

By the end of this lesson, you should be able to explain and apply the core ideas behind Building blocks and refinement in both exam questions and real architecture discussions.

Official alignmentLG 03-01 and LG 03-02.

Decomposition into building blocks

Architecture design breaks a system into meaningful building blocks with clear responsibilities and controlled dependencies.

E-Commerce
├── Catalog
├── Ordering
├── Payments
├── Shipping
└── Customer Management

Cohesion and coupling

Good decomposition aims for high cohesion inside building blocks and controlled coupling between them.

High cohesion

Responsibilities strongly belong together.

Low/controlled coupling

Dependencies are limited and intentional.

Black box vs white box

Black box

External responsibility, interface, inputs, outputs, guarantees.

White box

Internal structure and subcomponents.

Stepwise refinement

System
 ↓
Major subsystems
 ↓
Components
 ↓
Subcomponents

Refine gradually instead of attempting to design every detail at once.

Common CPSA-F exam traps

  1. Architecture design should start with frameworks. — Treat this as suspicious or false unless the context explicitly supports it.
  2. Black-box descriptions show internals. — Treat this as suspicious or false unless the context explicitly supports it.
  3. Low coupling means no communication. — Treat this as suspicious or false unless the context explicitly supports it.
  4. High cohesion means many unrelated responsibilities in one place. — Treat this as suspicious or false unless the context explicitly supports it.

Key terms to remember

DecompositionBreaking a system into meaningful building blocks.
Black boxExternal view of a building block.
White boxInternal structure of a building block.
Stepwise refinementProgressively decomposing architecture into finer structures.

Practical exercise

Design a food-delivery platform with Ordering, Restaurant, Delivery, Payment, and Notification concerns.

  1. Decompose the system into 4–6 building blocks.
  2. Define each block's responsibility.
  3. Choose one block and write a black-box description.
  4. Then create its white-box decomposition.

Review questions

What is decomposition?

Breaking a system into meaningful architectural building blocks.

What does a black-box view show?

Externally relevant responsibilities and interfaces.

What does a white-box view show?

Internal structure.

How to use this mock

The current official CPSA-F exam runs about 75 minutes with roughly 40 multiple-choice questions. The exact number varies because questions carry different point values. The official passing threshold is 60% of the maximum achievable points.

Questions: 40
Points per question: 1
Maximum: 40
Practice pass: 24/40
Time limit: 75 minutes
DisciplineAnswer all forty before opening a single answer. Reveal an answer early and you lose the diagnostic value of the weakness map at the bottom.

Part A — Fundamentals, requirements & drivers

Q1. Which statement best describes software architecture?

  1. The folder structure of the source code
  2. Fundamental structures, relationships, and significant design decisions
  3. A complete UML model of all classes
  4. The technology stack alone
Show answer

B — Architecture is broader than code layout or technology choice.

Q2. Which activity is most characteristic of a software architect?

  1. Personally making every implementation decision
  2. Reconciling architecturally significant concerns with stakeholders
  3. Avoiding business stakeholders
  4. Choosing every local variable name
Show answer

B — Architects reconcile significant concerns across stakeholders.

Q3. Which requirement is most likely to become an architecture driver?

  1. A button should use a specific label
  2. Orders must still be accepted while SAP is unavailable
  3. A helper method should be renamed
  4. One test should use different sample data
Show answer

B — Availability during an SAP failure materially changes the architecture.

Q4. Which statement about constraints is correct?

  1. Constraints always describe functionality
  2. Constraints restrict the available solution space
  3. Constraints are irrelevant to architecture
  4. Constraints may always be ignored
Show answer

B — Constraints restrict the solution space.

Q5. Why should assumptions be explicit?

  1. They can never be changed
  2. Wrong assumptions can create architecture risk
  3. They replace ADRs
  4. They are verified facts
Show answer

B — Hidden assumptions create unmanaged risk.

Q6. “95% of requests complete within 500 ms at 2,000 req/s” is primarily:

  1. A measurable quality requirement
  2. A coding convention
  3. A deployment rule
  4. A functional decomposition rule
Show answer

A — It is measurable and quality-focused.

Q7. Which statement about quality attributes is most accurate?

  1. All should be maximized equally
  2. They often involve trade-offs
  3. They matter only after implementation
  4. Performance is the only important one
Show answer

B — Qualities frequently conflict.

Q8. Which is the strongest example of an architecture-relevant constraint?

  1. Customer data must remain inside the EU
  2. A submit button says “Send”
  3. A method should be short
  4. A variable is called customerId
Show answer

A — Data residency restricts deployment and data design.

Part B — Design, decomposition, coupling & patterns

Q9. High cohesion means:

  1. Related responsibilities belong together
  2. Every component depends on every other
  3. One component contains unrelated responsibilities
  4. Everything is stored in one module
Show answer

A — Cohesion means related responsibilities belong together.

Q10. Which statement about coupling is most accurate?

  1. All coupling is bad
  2. Every dependency should be eliminated
  3. Dependencies should be appropriate, explicit, and controlled
  4. Coupling matters only in OO systems
Show answer

C — Dependencies should be intentional and controlled, not absent.

Q11. Stepwise refinement primarily means:

  1. Model everything in one diagram
  2. Progressively decompose architecture into suitable detail levels
  3. Avoid black-box descriptions
  4. Replace documentation with source code
Show answer

B — Refinement handles architecture at multiple abstraction levels.

Q12. A black-box description primarily shows:

  1. Every internal class
  2. Responsibility and externally visible interfaces
  3. Infrastructure nodes
  4. Source-code metrics
Show answer

B — Black boxes emphasize externally visible responsibility and interfaces.

Q13. Which statement about architecture patterns is correct?

  1. Patterns are always best practices
  2. Patterns are reusable approaches whose suitability depends on context
  3. Patterns remove trade-offs
  4. CPSA-F mandates microservices
Show answer

B — Pattern suitability depends on context.

Q14. A team chooses microservices because “modern companies use them.” What is wrong?

  1. Microservices cannot be documented
  2. The choice is not tied to architecture drivers and trade-offs
  3. Microservices cannot communicate over networks
  4. Microservices cannot be deployed independently
Show answer

B — Fashion is not an architecture driver.

Q15. Which situation most strongly signals problematic coupling?

  1. A stable module has one explicit dependency
  2. Adding one payment provider requires changes in unrelated modules
  3. A UI component uses a local helper
  4. A component exposes a documented API
Show answer

B — Broad change propagation indicates problematic coupling.

Q16. Good architecture decomposition should:

  1. Always use technical layers
  2. Support responsibilities, expected change, and architecture drivers
  3. Put all reuse into one global utility module
  4. Avoid interfaces between building blocks
Show answer

B — Boundaries should reflect responsibilities and expected change.

Part C — Interfaces, cross-cutting concepts & decisions

Q17. Useful interface documentation can include:

  1. Only method names
  2. Semantics, errors, constraints, timing, security, and versioning
  3. Developer schedules
  4. Only the programming language
Show answer

B — Interfaces are semantic and behavioral contracts.

Q18. Provided vs required interface:

  1. External vs internal
  2. Offered capability vs dependency on another capability
  3. Mandatory vs optional
  4. No difference
Show answer

B — Provided = offered; required = depended upon.

Q19. Which is semantic coupling?

  1. Two services use HTTPS
  2. A consumer depends on an undocumented meaning of status READY
  3. Two modules use different filenames
  4. A service uses JSON
Show answer

B — Undocumented meaning is semantic coupling.

Q20. Which is a cross-cutting concern?

  1. One variable name
  2. System-wide error handling
  3. One helper method
  4. One test record
Show answer

B — Error handling affects many building blocks.

Q21. Concern vs cross-cutting concept:

  1. Technology vs team
  2. Problem/topic vs coherent architecture solution
  3. Runtime vs deployment
  4. They are synonyms
Show answer

B — Concern = problem; concept = solution.

Q22. Why analyze interdependencies between cross-cutting concepts?

  1. They never influence each other
  2. Improving one concern may affect another quality or constraint
  3. They must use one technology
  4. They exist only in documentation
Show answer

B — One concept can affect other qualities.

Q23. Which choice most clearly deserves an ADR?

  1. Rename a local variable
  2. Choose durable asynchronous integration to protect availability
  3. Reorder imports
  4. Rename a test
Show answer

B — The integration decision has high architectural impact.

Q24. Main value of decision rationale:

  1. Prevent architecture from changing
  2. Preserve why the decision made sense in context
  3. Remove the need to document consequences
  4. Guarantee correctness
Show answer

B — Rationale preserves architectural knowledge.

Q25. Which ADR statement is correct?

  1. One mandatory iSAQB template exists
  2. ADRs preserve context, decision, rationale, and consequences
  3. Every small coding choice needs one
  4. Old ADRs should be silently overwritten
Show answer

B — ADR format is flexible; knowledge preservation is what matters.

Part D — Feedback, risk & iteration

Q26. Why are short feedback loops valuable?

  1. They guarantee first-time correctness
  2. They test assumptions and risks earlier
  3. They eliminate decisions
  4. They guarantee consensus
Show answer

B — Early feedback lowers the cost of wrong assumptions.

Q27. Which decision most strongly deserves early validation?

  1. A reversible low-impact library choice
  2. A high-impact, uncertain, hard-to-reverse partitioning strategy
  3. Variable naming
  4. Comment formatting
Show answer

B — High impact + uncertainty + low reversibility deserves validation.

Q28. Which statement about iterative architecture is correct?

  1. It means no upfront reasoning
  2. Decisions can be refined as evidence becomes available
  3. It eliminates risk
  4. Documentation becomes unnecessary
Show answer

B — Iteration refines decisions with evidence.

Q29. Strongest evidence for a scalability assumption:

  1. Rename a component
  2. Representative load test
  3. Add architecture slides
  4. Ask only the original proposer
Show answer

B — Load tests directly test scalability assumptions.

Part E — Documentation & views

Q30. Which view shows the system boundary and external systems?

  1. Runtime
  2. Context
  3. Building block
  4. Deployment
Show answer

B — Context shows the environment and system boundary.

Q31. Which view shows static software decomposition?

  1. Context
  2. Runtime
  3. Building block/component
  4. Deployment
Show answer

C — The building block view shows static software structure.

Q32. Which view best shows what happens when Payment times out?

  1. Runtime
  2. Context
  3. Deployment
  4. Glossary
Show answer

A — Runtime shows dynamic interactions and failures.

Q33. Which view best shows where Payment Service runs and what infrastructure it uses?

  1. Context
  2. Runtime
  3. Deployment
  4. Requirements
Show answer

C — Deployment maps software to infrastructure.

Q34. Which statement is correct?

  1. Architectural view = UML
  2. A view is a perspective; UML/C4 can be notation
  3. Every runtime view must be a UML sequence diagram
  4. C4 is mandatory
Show answer

B — A view is a perspective; notation is how it is expressed.

Part F — Analysis & conformance

Q35. Architecture analysis:

  1. Can only happen after release
  2. Can happen before, during, or after implementation
  3. Checks only functional correctness
  4. Replaces testing
Show answer

B — Architecture can be analyzed at design time and at runtime.

Q36. Which is quantitative evidence?

  1. “The design seems complex.”
  2. “p95 latency is 1.2 seconds under expected load.”
  3. “The team dislikes the design.”
  4. “Responsibilities seem unclear.”
Show answer

B — A measured latency value is quantitative evidence.

Q37. A component has 18 outbound dependencies. Best conclusion?

  1. Architecture is definitely wrong
  2. Split it immediately
  3. It is a signal requiring contextual interpretation
  4. Reduce dependencies to zero
Show answer

C — Metrics are signals, not automatic verdicts.

Q38. Architecture conformance primarily evaluates:

  1. Whether implementation aligns with architecture design and decisions
  2. Business profitability
  3. IDE consistency
  4. Stakeholder agreement
Show answer

A — Conformance compares implementation with architecture intent.

Q39. Drift vs erosion:

  1. Drift = deviation; erosion = accumulated degradation of architecture properties
  2. Drift = runtime-only; erosion = documentation-only
  3. Drift is always intentional
  4. They are identical
Show answer

A — Erosion is accumulated harmful drift.

Q40. Strongest automated architecture check:

  1. “Architecture should feel clean.”
  2. “No domain class may depend on infrastructure packages.”
  3. “Developers should write elegant code.”
  4. “The system should be modern.”
Show answer

B — The rule is explicit, architecture-relevant, and mechanically checkable.

- Fraud API sometimes takes 8 seconds.

- A new document provider is planned.
- Several services read Customer DB directly.
- Two teams use different retry policies.
- No architecture tests exist.

Prepare an architecture review with:

  1. Top 5 architecture drivers
  2. Top 5 risks
  3. One availability scenario
  4. One modifiability scenario
  5. Three proposed architecture decisions
  6. Two cross-cutting concepts needing standardization
  7. Three rules suitable for automated checking
  8. One runtime fitness function
  9. The ADR you would write first
  10. The views you would use to communicate the design
Staff Engineer lensStrong answers link evidence + architecture driver + trade-off. A risk list with no driver behind it is just a list of things you dislike. Day 21 works this exact case through in full.

Exam strategy

Duration: about 75 minutes
Questions: roughly 40
Format: multiple choice
Pass threshold: 60%

Suggested pacing:

First 45 min:  Answer confident questions.
Next 20 min:   Resolve uncertain questions.
Final 10 min:  Review wording and mistakes.

Watch especially for absolute words:

always
never
only
all
must
Rule of thumbDo not choose an answer because it names a fashionable technology. Ask: which option best addresses the architectural concern actually being tested?

Key terms checklist

Make sure you can explain these without notes: software architecture · stakeholder · concern · requirement · constraint · quality requirement · architecture driver · assumption · architectural decision · ADR · cohesion · coupling · black box · white box · pattern · interface contract · provided interface · required interface · cross-cutting concern · cross-cutting concept · feedback loop · architecture risk · context view · building block view · runtime view · deployment view · qualitative analysis · quantitative analysis · quality scenario · architecture metric · architecture conformance · architecture drift · architecture erosion · fitness function.
